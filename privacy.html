应用介绍隐私说明使用说明

隐私说明

适用于 Hermes Calendar 的个人自用部署及其与 Home Assistant 的日历协作。部署由使用者自己管理，不设公众账户注册或独立运营的用户数据库。

访问什么数据，为什么访问

Hermes 读取日历列表、日历标识和访问权限以识别主日历；读取事件标题、起止时间、时区、描述、地点、全天标记、重复规则、取消状态和版本标识，用于日程查询、明确请求的事件修改、摘要、提醒与去重。日历标识可能包含账户邮箱。

Hermes 的 calendar.events.owned 权限允许管理账号所拥有日历的事件，运行时将操作限定在主日历；calendar.calendarlist.readonly 用于读取日历列表。Home Assistant 的独立客户端使用 calendar.readonly 读取日历数据，面板按配置展示所选主日历。OAuth 权限覆盖范围与面板选择范围并不相同。

日程页面显示事件标题和时间；使用者点击事件时，可在自己的 Home Assistant 中查看详情，包括事件描述。明确启用家居联动时，NAS 还使用事件实例、开始时间和经许可的场景对应关系来安排动作；普通事件描述不被视为任意设备操作指令。

存储位置与保留

Hermes 的 OAuth 客户端凭据、访问令牌、刷新令牌、日程缓存、事件防重标识、通知及动作执行记录保存在使用者 NAS 的私有目录。Home Assistant 的独立令牌、同步缓存和相关记录保存在 NAS 上的 Home Assistant 配置与数据目录。访问控制、日志和备份由部署所有者管理；这里不宣称这些目录天然加密或完全没有日志。

缓存和账本支持同步、去重及排错。没有统一的自动删除期限：实际保留时间取决于部署配置、日志策略和备份管理。公开说明网站与公开静态文件不保存 OAuth 令牌、真实日程或设备清单。

这些静态说明页面没有登录表单、统计脚本或第三方嵌入内容。网站托管平台仍可能按自身规则产生访问日志。

传输给哪些服务

  • Google：OAuth 登录和日历 API 请求由官方端点处理。应用不要求使用者把 Google 密码交给 Hermes。
  • Telegram：启用通知后，摘要、事件标题和时间等提醒内容通过 Bot API 发送到使用者指定的对话，并记录投递结果。
  • 配置的模型服务：仅在使用者主动进行自然语言日程交互时，相关对话及必要的日历工具结果可能随请求发送给该服务。工具结果可能包含标题、描述和地点。定时摘要、提醒和明确场景调度不将日历内容交给模型生成。
  • Home Assistant 与设备集成：自己的浏览器访问 HA 日程页面；经明确授权的场景由 HA 执行。设备命令是否经过设备厂商云端，取决于对应集成。

Google 日历和 Telegram API 通过 HTTPS 访问。NAS、本地 HA 访问及设备链路的保护方式由部署配置决定。本应用不保证外部服务从不保留数据；Google、Telegram、模型服务和设备服务的日志、保留及其他处理规则，以相应服务说明和账号配置为准。

用途限制

日历数据用于以上面向使用者的日程管理、显示、通知、明确场景执行和必要排错。本应用不提供出售日历数据、广告投放或以日历数据训练模型的功能。Google API 数据的访问与使用须遵循 Google API Services User Data Policy，包括适用的 Limited Use 要求；这不代表 Google 已审核或认证本部署。

撤销、停用与删除

使用者可在 Google 账户的第三方连接设置中检查并撤销对应应用授权，也可分别停用 Hermes 定时任务、家居场景调度或 HA 集成。撤销 Google 授权不会自动删除已有 Google 日程或本地历史记录；有关操作见 Google 的连接管理说明。

删除本地数据时，应先停用相关组件，再由部署所有者清理令牌、HA 集成数据、缓存、账本、相关日志及备份。Telegram 已发送消息需另外通过 Telegram 的删除功能处理；模型等外部服务中的记录按各自的数据控制方式管理。

联系

这是由使用者管理的个人部署。授权或数据处理问题可联系 Google 授权页面所显示的应用支持邮箱。本公开页面不展示实际邮箱或账户身份。
